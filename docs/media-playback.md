# 媒体播放

[文档导航](README.md) · [架构导航](architecture.md) · [验证指南](testing.md)

## 入口与职责

独立视频/音频统一由 `jark::isPlayerFile()` 判定，命令行、拖放、Ctrl+O 三处一致；视频与音频扩展名不混入看图的 `supportExt`。代码列表与两份 README 由源码不变量检查核对。

`VideoPlayerApp` 是独立于查看器的顶层窗口，通过入口接力循环切换；不构造看图缓存、导航浮层或设置工具窗。它复用 `CanvasRenderer` 画帧，`UiHost` 画浮层，输入由播放器自行命中处理，不能落回看图快捷键分支。

| 模块 | 职责 |
| --- | --- |
| `MappedFileReader` | 整文件只读映射，不把大视频完整复制到内存 |
| `MediaDecoder` | 解复用、视频解码、旋转、音频重采样，支持按流过滤 |
| `AudioOutput` | XAudio2 输出、缓冲管理、已播放样本时钟 |
| `MediaPlayer` | 两路解码线程、队列、时钟同步与 EOF |
| `VideoPlayback` | 播放/暂停、步进、拖动节流与落位状态机 |
| `VideoPlayerApp` | 适应窗口显示、条带、信息面板、纯音频画面 |
| `AudioSpectrumAnalyzer` | 带媒体时间戳的 PCM 频谱分析 |

映射必须比解码器/播放器活得久，`MediaDecoder::open()` 只持有 span。关闭时先 stop，再释放映射。播放器映射路径没有旧的 256 MiB 整文件读取上限；不能据此假定实况照片/探针等整文件加载路径也没有限制。

## 两路解码与主时钟

有视频和音频时各用一个 `MediaDecoder` 和线程，`StreamFilter` 使各自只解一路。视频受有限帧队列背压，音频受声卡队列背压；不要为省实例合为一条循环，否则视频队满可能阻断音频，音频时钟停住后又无法消费视频，形成自锁。

音频统一重采样为 48 kHz、立体声、16 位。声卡可用时以已播放样本数为主时钟，创建失败时静音并回退系统时钟，暂停/seek 仍须可用。音轨短于视频时补静音至媒体总时长，避免最后几帧永远等不到时钟。

## 音频缓冲生命周期

- 同时按样本数和缓冲区数量背压；XAudio2 单 voice 最多 64 个缓冲，仅按时长限流不足。提交失败保留数据重试，不能丢掉一批音频。
- `SubmitSourceBuffer` 不复制 `pAudioData`。内存必须保留到 `OnBufferEnd` 或引擎彻底销毁，`Stop` + `FlushSourceBuffers` 不保证正在播放的那块已用完。
- flush / stop 将未完成缓冲转入 `retiredBuffers`；收到完成回调的记录及时释放，最终兜底在 `IXAudio2::Release()` 之后进行。
- UI 的 pause/resume 与后台 submit/flush 在同一 `stateMutex` 下互斥，防止刚暂停又按旧 `autoStart` 起播。
- flush / stop 后按当下 `SamplesPlayed` 重建提交计数基线，不能假定计数清零。暂停保留队列与位置，seek 才清队列。

`--audio-test` 验证队列、时钟、提交重试和暂停；带音轨的 `--video-test` 还要覆盖重复 seek，单纯自然播放无法覆盖缓冲 use-after-free。

## seek 与拖动

seek 是异步命令，序号、目标和模式在 `seekMutex` 内成组发布，只执行最新序号。发布时立即清旧视频队列；两路完成定位、设置时钟基线后才允许交帧与判 EOF，避免 UI 把尚未清掉的旧帧当作新落点。

- 每个解码器按自己负责的流选择 `stream_index` 与时间基，再 `AVSEEK_FLAG_BACKWARD` 回到目标前的关键帧；音频不能跟着默认视频流退到很早的关键帧。
- 精确落点靠视频丢帧、音频裁样本；视频的 `setSkipBeforeMs()` 在回读/缩放/拷贝之前过滤，长 GOP 无需为大量无用帧付出转换成本。
- 音频先连续 resample 再裁目标前样本，同时更新批次 PTS；全批早于目标则丢弃并继续。不能只在播放端裁第一批，也不能跳过重采样输入而破坏历史。seek 清重采样器旧历史。
- 时钟基线只有一个写者：声卡可用时由音频侧写，系统时钟通常由视频侧写；无视频的纯音频路径自行重建系统时钟基线。
- 两路线程到 EOF 后等待下一次 seek，不直接退出。视频结尾判定留适当帧余量，纯音频按媒体总时长判断。

拖动三条语义由 `--video-test` 验证：

1. 按下即暂停并 capture，拖出控件/客户区仍继续；拖动中时钟停在目标位置。
2. 约 60 ms 节流的 `KeyFrame` 预览每次只交一帧，`previewHold` 阻止随后旧帧追赶播放；最后被节流的目标到期补发，不能丢。
3. 松手发 `Exact` seek，等实际交付帧达到目标附近再恢复；不能只看 worker 的“在途”标记。取消/失捕获也必须收尾。

## 纯音频

没有视频轨时不建视频线程，所有“是否有媒体”守卫都按 `videoDecoder || audioDecoder`，包括 stop / pause / resume / seek。否则声音可能在切换或析构后继续运行。

没有视频帧的输入不能等待“落点帧”：`endScrub()` 直接按音频落点恢复，暂停下左右步进退化为 ±5 秒。`--video-test` 对音频跑时钟、暂停、seek、EOF、重播和拖动的无帧断言。

`InfoScreen::renderAudio()` 缓存静态底板，`drawAudioSpectrum()` 叠加实时条，不每帧重排整幅文字。信息面板共用 `UiHost::drawWrappedText()` 的折行/滚动逻辑，`mediaInfoText()` 生成可测试的路径、时长、格式和流参数文本。

## 解码与硬件加速

目前只使用 D3D11VA；缺少配置、无设备或驱动失败时回退同编码器的软件解码。硬解设置为 `thread_count=1`，避免帧级线程竞争与多份硬解池放大显存、seek 延迟。AV1 当前优先选到 libdav1d，因此实际走软件。

- 硬解帧先 `av_hwframe_transfer_data` 回读 CPU，再走 sws / 旋转 / clone；精确 seek 的丢帧判断尽量排在回读之前。
- 全范围 yuvj 片源回读为 NV12 后可能丢失 range 语义，按 `sw_pix_fmt` 给 sws 补源全范围信息，避免发灰。
- 运行期失败只在尚未交付视频帧时重开软解并退回落点；已交帧后重开会交付重复时间戳。验证用 `--hw-test`，开局回退另做 [故障注入](debugging.md#硬件解码)。
- `MediaInfo::width/height` 是未旋转编码尺寸，`displayWidth()/displayHeight()` 是显示尺寸。播放端使用后者；帧可能因长边限制降采样，要求宽高比一致，不要求帧像素尺寸等于名义尺寸。

独立视频与实况照片共用该链路；相关修改都要跑状态机、播放流畅度、音频和硬软解对照。

## 播放器画面

- 固定适应窗口，缩小用 `INTER_AREA`、放大用 `INTER_LINEAR`，1:1 跳过。先重采样到显示矩形，再以 1:1 画到画布；直接复用最近邻采样会放大成块。
- resize / DPI 变化重建上传纹理后，立刻重画并上传当前帧；只 `markPresentRequested()` 无法补回空纹理，暂停时没有下一帧兜底。
- 底部条带使用主题半透明背景，已播/未播分别画在左右两段，不能将两层半透明整条重叠而混色。时间叠白字/深底，深浅主题均可读。
- 视频条带由悬停瞬时显示，拖动期间保持；纯音频常驻。隐藏时不参与命中，打开失败不画条带。信息面板滚轮不穿透到音量。
- 播放器 ImGui 浮层不接管输入；单击画面需按下/抬起都落在画面，防止条带拖动松手误切暂停。

窗口交接与几何保存见 [架构导航](architecture.md#持久设置)；用户快捷键以两份 README 和实际输入处理为准，不在此复制完整清单。

## 频谱

只在纯音频画面启用。解码线程喂与声卡相同的 PCM，分析不受音量影响，也不依赖声卡回环。

`AudioSpectrumAnalyzer` 下混单声道、去直流、做 Hann 窗 FFT，聚合为对数频段并快起慢落。电平按固定 dB 范围映射，不做 AGC，保证静音与已知输入有可断言的数值。

- 每帧带媒体 PTS，环形缓冲按 `MediaPlayer::positionMs()` 取不晚于播放位置的最新帧；直接取最新分析结果会提前约一个音频预提交队列。
- 进 FFT 前去直流，相邻频段不重复使用同一 bin，避免最低几根常亮和频段偏移。
- seek 时 reset 旧帧；`--spectrum-test` 覆盖频段、电平、衰减、去直流和按播放位置取帧。
